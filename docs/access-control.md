# 用户组与管理后台

当前运行数据库为 PostgreSQL，角色与权限规则保持。管理员脚本通过 DATABASE_URL 操作指定 PostgreSQL；旧 SQLite 升级记录属于历史，当前迁移方法见 [PostgreSQL 说明](postgresql.md)。

当前工程角色为 `user`（普通用户）和 `stuff`（管理员，沿用用户指定拼写）。游客是未登录状态，不是数据库角色。

| 功能 | 游客 | user | stuff |
| --- | --- | --- | --- |
| 已发布活动 / 公开书目 | 可读 | 可读 | 可读 |
| 个人资料、本人报名和反馈 | 不可 | 仅本人 | 个人入口仍仅本人 |
| 新建本人报名 / 提交符合资格的活动反馈 | 不可 | 可 | 可 |
| 用户管理、全部报名/反馈、草稿活动 | 不可 | 不可 | 可 |
| 用户角色调整、账号停用/启用 | 不可 | 不可 | 可，不能停用/降级自己 |
| 活动新增/编辑、发布/下线 | 不可 | 不可 | 可 |
| 操作日志 | 不可 | 不可 | 可读 |

后端从数据库会话读取身份和最新角色；公开注册忽略用户提交的 role，默认 user。个人资料只允许修改本人的昵称、性别、地区和签名；新增字段不出现在后台或会话概要中。修改密码需要验证当前密码，成功后撤销该账号全部会话。后台读写要求启用的 stuff 会话，列表不查询密码或会话字段。

管理界面地址：`/#admin`。含工作概览、用户管理、报名管理、反馈管理、活动管理、操作记录。用户/报名/反馈有搜索与分页，报名和反馈有状态筛选。管理员登录后默认进入反馈列表（`#admin/feedbacks`）。

「我的」会员中心位于 `/#mine`：登录用户在一页查看个人资料摘要、报名记录与本人反馈（含门店回复），并可进入设置。未登录访问时提示登录。顾客登录后进入该页，管理员登录后进入反馈列表。

用户管理允许调整称呼、邮箱、用户组和启用状态。邮箱重复会拒绝；密码不在后台展示或修改。邮箱、角色或启用状态变化时撤销该账号全部会话。停用不删除历史业务数据。

报名管理允许修改姓名和电话、取消/恢复和签到。恢复时仍在事务中检查余位及有效报名唯一性；活动未开始不能标记签到。活动容量不得低于现有有效报名人数。

反馈管理允许设置待处理/处理中/已回复/已关闭并填写回复；标记已回复必须有回复内容。反馈原文和评分由用户提交，管理员不会覆盖原文。回复仅在提交者的「我的」会员中心及后台显示。

反馈资格由 `server/feedback-policy.js` 统一计算，入口状态与提交校验共用同一策略：已签到的报名可立即填写；未签到的有效报名需等活动结束；已取消或已提交的报名不可填写。报名列表接口返回 `can_feedback` 与 `feedback_state`（`waiting`/`available`/`cancelled`/`submitted`）供界面显示入口。同一报名重复提交返回冲突，不产生第二条反馈。

每次管理修改在同一事务内写入操作日志。日志记录操作者、动作、目标和时间，不复制用户密码或联系资料。

初始化管理员：新建账号运行 `npm run create-admin`；已有账号运行 `npm run create-admin -- --promote`，按提示输入选定邮箱。CLI 授权记录使用 bootstrap_administrator 动作；这是本地拥有数据库权限的初始化操作。

v1 用户表升级会先创建数据库备份，保留 ID 和外键关系。reader 映射为 user，staff/manager 映射为 stuff。数据库文件和升级备份都属于私有运行数据。
